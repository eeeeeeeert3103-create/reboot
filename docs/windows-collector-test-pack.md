# REBOOT: тест-пак Windows-коллектора (`reboot/collector`)

**Статус:** код написан на macOS без MSVC, CMake и Windows. **Сборка и запуск не проверялись.** Все пункты ниже — план проверки (`NOT RUN`). Отмечайте результат только после реального прогона на Windows.

Что проверяем: нативный коллектор `windows/runner/usage_collector.{h,cpp}`. Он реализует контракт v1 канала `reboot/collector`: `getStatus`, `requestPermission`, `start {userConsent}`, `stop`, `drainEvents`.

Что коллектор собирает:
- имя exe активного процесса в нижнем регистре (`chrome.exe`);
- `FileDescription` из версии файла (если её нет — имя exe без `.exe`);
- периоды бездействия: больше 120 с без ввода;
- блокировку и разблокировку сессии, сон и пробуждение.

Что коллектор **не** собирает: заголовки окон, полные пути, URL, нажатия клавиш, скриншоты, содержимое приложений. Сети нет.

Нужны Visual Studio 2022 с нагрузкой **«Разработка классических приложений на C++»** (MSVC, Windows 10/11 SDK, CMake) и Flutter 3.47.9.

## 1. Окружение и сборка

Выполните в PowerShell из корня репозитория:

```powershell
flutter --version          # ожидается Flutter 3.47.9
flutter doctor -v          # пункт "Visual Studio - develop Windows apps" без ошибок
flutter config --enable-windows-desktop
flutter pub get
flutter build windows --release
```

Ожидается: сборка проходит без ошибок. Runner собирается с `/W4 /WX`, поэтому любое предупреждение в `usage_collector.cpp` остановит сборку. Если так случилось, запишите полный текст ошибки: файл, строку и код `C4xxx`.

Где лежит exe:

```
build\windows\x64\runner\Release\reboot_app.exe
```

На ARM64-машине путь будет `build\windows\arm64\runner\Release\reboot_app.exe`. Рядом с exe должны лежать `flutter_windows.dll` и папка `data\`. Запускайте exe только из этой папки или копируйте её целиком.

Запуск:

```powershell
.\build\windows\x64\runner\Release\reboot_app.exe
```

Для отладки с консолью и логами Dart подойдёт `flutter run -d windows`. Коллектор работает одинаково в debug и release.

## 2. Где лежат данные

- Локальные данные REBOOT: `%LOCALAPPDATA%\REBOOT\`. Чтобы открыть папку, выполните `explorer "$env:LOCALAPPDATA\REBOOT"`.
- Нативный коллектор **ничего не пишет на диск**. События лежат в памяти, в буфере до 20 000 штук, пока Dart не заберёт их через `drainEvents`. Dart опрашивает коллектор каждые 30 с, при сворачивании и закрытии приложения, и сам сохраняет сессии в `%LOCALAPPDATA%\REBOOT\`.
- Проверка приватности: откройте файлы в этой папке текстовым редактором и найдите своё имя пользователя Windows (`$env:USERNAME`), `C:\Users`, `http` и заголовки открытых окон. **Ожидается: ничего из этого не найдено.**

## 3. Ручной чек-лист

Перед каждым сценарием REBOOT запущен, согласие на сбор дано, статус «Идёт сбор…». Время считайте по часам Windows. Если в интерфейсе Dart нет экрана сырых событий, проверяйте по экрану сессий или аналитики.

### 3.1 Статус и согласие — `NOT RUN`
1. Сразу после первого запуска, до согласия: статус `ready`, `collecting=false`. Сообщение по-русски: «Готово к запуску…».
2. `start` без согласия (`userConsent` ≠ `true`) возвращает ошибку `consent_required`, сбор не начинается.
3. После согласия: `lifecycle=collecting`, `collecting=true`, `permissionGranted=true`, `platform=windows`.
4. Повторный `start` ничего не дублирует. `stop` даёт статус `stopped`, повторный `stop` ничего не делает.

### 3.2 Переключение приложений — `NOT RUN`
1. По очереди активируйте на 20–40 с: Блокнот, Проводник, браузер, REBOOT.
2. Ожидается: для каждого приложения отдельная сессия, длительность совпадает с секундомером ±2 с. `appIdentifier` — имя exe (`notepad.exe`, `explorer.exe`, `chrome.exe`/`msedge.exe`, `reboot_app.exe`). `displayName` — человекочитаемое имя («Блокнот» / «Notepad», «Проводник», «Google Chrome», «Microsoft Edge»).
3. Ожидается, что заголовков окон, имён файлов и URL нигде нет.
4. Откройте **Калькулятор** и **Параметры** Windows (UWP). Ожидается: `calculatorapp.exe` или `systemsettings.exe`, а не `applicationframehost.exe`. Если видно `applicationframehost.exe`, запишите это как известное ограничение и укажите приложение.
5. Окно с правами администратора (например, «Диспетчер задач»): ожидается `taskmgr.exe`. Если процесс не удалось открыть, время этому окну не засчитывается.

### 3.3 `appLaunched` — `NOT RUN`
1. Закройте Блокнот, запустите его заново и активируйте.
2. Ожидается событие `appLaunched` для `notepad.exe`: это первая активация нового процесса за время работы коллектора.
3. Приложения, запущенные до старта сбора, тоже получат `appLaunched` при первой активации. Это задокументированное поведение, а не ошибка.

### 3.4 Бездействие 2+ минуты — `NOT RUN`
1. Активируйте Блокнот, отметьте время T0 и **не трогайте** мышь и клавиатуру 3 минуты.
2. Ожидается: сессия Блокнота заканчивается примерно в T0, а не через 2 минуты. Событие `idleStarted` получает время последнего ввода. Через 120–125 с бездействия засчитанное время перестаёт расти.
3. Пошевелите мышью. Ожидается в течение 5 с: `idleEnded`, затем новая сессия текущего приложения.
4. Видео без ввода (YouTube в полноэкранном режиме 3+ минуты) тоже считается бездействием. Это известное ограничение.

### 3.5 Блокировка Win+L — `NOT RUN`
1. Активируйте браузер, нажмите **Win+L**, подождите 1 минуту и разблокируйте.
2. Ожидается: сессия браузера закрыта в момент блокировки, затем `sessionLocked`. После разблокировки идёт `sessionUnlocked` и новая сессия активного приложения. Время на экране блокировки не засчитано.
3. Если статус говорит «Блокировку экрана Windows отследить не удалось», значит `WTSRegisterSessionNotification` не сработал. Запишите это.

### 3.6 Сон и пробуждение — `NOT RUN`
1. Пуск → Завершение работы → **Спящий режим**. Подождите 2+ минуты и разбудите компьютер.
2. Ожидается: сессия закрыта в момент засыпания, `sessionLocked` (сон отчитывается как блокировка). После пробуждения и входа — `sessionUnlocked` и новая сессия. Событий `sessionLocked`/`sessionUnlocked` не два подряд, время сна не засчитано.
3. На машинах с Modern Standby (S0) Windows может не прислать `PBT_APMSUSPEND`. Тогда сработает блокировка сессии или защита по разрыву таймера: сегмент закрывается, если между тиками прошло больше 15 с. Запишите, что именно наблюдалось.

### 3.7 Повторный запуск и закрытие — `NOT RUN`
1. Поработайте 2 минуты, закройте REBOOT крестиком, через 1 минуту запустите снова.
2. Ожидается: данные до закрытия сохранены (Dart забирает их при закрытии). Время, пока REBOOT был закрыт, **не** засчитано никому: сбор идёт только пока REBOOT запущен. После повторного запуска с уже данным согласием сбор продолжается.
3. Завершите `reboot_app.exe` через Диспетчер задач. Ожидается потеря не больше одного интервала опроса Dart (≤ 30 с), остальные данные на месте.

### 3.8 Длительная работа — `NOT RUN`
1. Оставьте REBOOT работать 1+ час при обычной работе.
2. Ожидается: потребление CPU близко к нулю, память не растёт (Диспетчер задач → Подробности → `reboot_app.exe`).

### 3.9 Значок в трее и меню (`reboot/app`) — `NOT RUN`
Нативная часть: `windows/runner/app_shell.{h,cpp}`. Сценарии 3.9–3.13 требуют Dart-стороны `lib/services/app_shell.dart`. Без неё проверяются только пункты, помеченные «без Dart».
1. Обычный запуск (контракт v1.1): значок REBOOT в области уведомлений появляется сразу и виден всё время работы. Это значок приложения, не пустой и не стандартный. Если Windows прячет его в «скрытые значки» (стрелка ^), это нормально. `getAppState` возвращает `backgroundMode=true`, `windowVisible=true`, `startedInBackground=false`, `trayAvailable=true`.
2. `setBackgroundMode {enabled:false}` (без Dart: через отладку) возвращает состояние с `backgroundMode=true`. Значок остаётся, крестик по-прежнему прячет окно.
3. Наведите курсор на значок. Подсказка: `REBOOT — <первая строка статуса>`, не длиннее 127 символов. До первого `updateStatus` подсказка просто `REBOOT`.
4. Щёлкните по значку левой кнопкой, затем правой. Оба раза открывается одно и то же меню, по одному разу, без дублей. Порядок: серые строки статуса (2–4, нажать нельзя), разделитель, «Открыть REBOOT» (жирным), «Остановить сбор» или «Возобновить сбор», разделитель, «Завершить REBOOT».
5. Откройте меню и щёлкните мимо него: меню закрывается. Нажмите Esc: меню закрывается.
6. Клавиатура: Win+B, стрелками до значка, Enter. Открывается то же меню.
7. Пока сбор идёт, пункт называется «Остановить сбор». После выбора Dart получает `trayAction {action: toggleCollection}`, а после нового `updateStatus` с `collecting=false` пункт называется «Возобновить сбор».
8. Строка статуса с символом `&` (например, `Сон & отдых`) показывается с `&`, без подчёркнутой буквы.
9. Перезапустите Проводник: Диспетчер задач → «Проводник» → «Перезапустить». Ожидается: через несколько секунд значок REBOOT снова на месте (обработка `TaskbarCreated`), меню работает.
10. Значок не пропадает ни при открытом, ни при скрытом окне. Он исчезает только при завершении процесса.

### 3.10 Закрытие окна в фоновом режиме — `NOT RUN`
1. Окно открыто. Нажмите крестик. Ожидается: окно исчезает, процесс `reboot_app.exe` жив (Диспетчер задач), значок в трее на месте. Dart получает `windowVisibilityChanged {visible:false}`, а `didRequestAppExit` / `onExitRequested` **не** вызывается.
2. То же через Alt+F4 и через «Закрыть окно» в контекстном меню кнопки на панели задач. Результат такой же.
3. В скрытом состоянии сбор продолжается. Через 5 минут откройте окно и проверьте, что сессии за это время записаны.
4. «Открыть REBOOT» в меню трея: окно появляется поверх остальных и получает фокус. Если окно перед этим было свёрнуто, оно разворачивается. Dart получает `trayAction {action: open}` и `windowVisibilityChanged {visible:true}`. Если Windows только мигает кнопкой на панели задач вместо перевода окна на передний план (защита фокуса), запишите это.
5. Отдельно проверьте `showWindow` из Dart без щелчка по трею: окно показывается. Если оно не выходит на передний план, а только мигает, это ограничение Windows; запишите.
6. Завершить REBOOT можно только через «Завершить REBOOT» в трее или через `quit` из Dart. Крестик приложение не закрывает.
7. Выключение и выход из Windows. Окно открыто или скрыто, нажмите «Пуск» → «Завершение работы» (или «Выход»). Ожидается: Windows не показывает «Это приложение препятствует завершению работы» из-за REBOOT, и выключение не отменяется. Данные с последнего опроса Dart (≤ 30 с) могут не сохраниться — это известное ограничение.
8. Перезапустите Проводник и, пока его нет, нажмите крестик. Окно не прячется, а закрывается обычным образом: без значка вернуться к скрытому окну было бы нельзя.

### 3.11 Завершение из трея — `NOT RUN`
1. Окно скрыто. Выберите «Завершить REBOOT». Ожидается: Dart получает `trayAction {action: quit}`, сохраняет данные и вызывает `quit`. Процесс завершается меньше чем за 4 с, значок пропадает сразу, а не после наведения мыши.
2. После перезапуска данные до момента выхода на месте.
3. Страховочный таймер (без Dart или при зависшем Dart): если `quit` не пришёл, процесс завершается сам примерно через 4 с после выбора пункта, значок исчезает. Засеките время.
4. Выберите «Завершить REBOOT» и сразу откройте меню трея ещё раз. Процесс всё равно завершается (меню закрывается само), без падения и без «мёртвого» значка.

### 3.12 Запуск с `--background` — `NOT RUN`
1. Закройте REBOOT. Запустите `.\reboot_app.exe --background` из папки сборки.
2. Ожидается: окно не появляется, даже на мгновение. Значок в трее есть сразу, процесс в Диспетчере задач есть. `getAppState`: `startedInBackground=true`, `windowVisible=false`.
3. Dart запускается в фоне: сбор начинается (при данном согласии) без открытия окна. Проверьте через 2–3 минуты по сессиям.
4. «Открыть REBOOT» из меню: окно показывается с нормальным содержимым, без белого или чёрного прямоугольника. Если содержимое появилось только после изменения размера окна, запишите.
5. Без `--background` окно открывается как обычно, `startedInBackground=false`.
6. Если в момент запуска с `--background` значок добавить нельзя (область уведомлений недоступна), окно должно открыться сразу. Процесса без окна и без значка быть не должно.
7. Второй экземпляр. REBOOT запущен, окно скрыто в трей. Запустите `reboot_app.exe` ещё раз без аргументов. Ожидается: второй процесс сразу завершается с кодом 0, а окно первого появляется поверх остальных; Dart первого получает `windowVisibilityChanged {visible:true}`. Повторите с `reboot_app.exe --background`: ничего не показывается, второй процесс завершается. Во всех случаях в Диспетчере задач один `reboot_app.exe`, в трее один значок.

### 3.13 Автозапуск — `NOT RUN`
1. `setLaunchAtLogin {enabled:true}`. Проверьте в PowerShell:
   ```powershell
   Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run' -Name REBOOT
   ```
   Ожидается значение `"<полный путь>\reboot_app.exe" --background` (путь в кавычках). Права администратора не нужны, в `HKLM` ничего не пишется.
2. `getAppState`: `launchAtLogin=true`, `launchAtLoginStatus=enabled`, сообщение по-русски.
3. Выйдите из учётной записи Windows и войдите снова. Ожидается: REBOOT запустился в фоне, окна нет, значок в трее есть, сбор идёт.
4. Параметры → Приложения → Автозагрузка (или Диспетчер задач → Автозагрузка): отключите REBOOT. Ожидается: `launchAtLoginStatus=requiresApproval`, сообщение подсказывает, где включить. Это определяется по недокументированному ключу `StartupApproved\Run`; если статус не изменился, запишите.
5. `setLaunchAtLogin {enabled:false}`: значение `REBOOT` удалено из ключа `Run`, статус `disabled`. Повторное выключение не даёт ошибки.
6. Перенесите папку сборки в другое место и запустите оттуда, не меняя автозапуск. Ожидается: `launchAtLoginStatus=error`, сообщение про другой путь. Повторное включение исправляет путь.
7. Ошибка записи (например, временно запретите себе запись в ключ `Run` через `regedit` → «Разрешения»). Ожидается: `FlutterError` с кодом `launch_at_login_failed` и русским сообщением с кодом ошибки. Затем верните разрешения.

### 3.14 `getFrontmostApp` и `limitApp` — `NOT RUN`
1. Откройте Блокнот, сделайте его активным и через 2–3 с вызовите `getFrontmostApp` (из Dart по таймеру или из отладки). Ожидается `{appIdentifier: "notepad.exe", displayName: "Блокнот"}` (или «Notepad»), как в событиях коллектора из 3.2. Это работает, даже если сбор остановлен.
2. UWP: Калькулятор активен. Ожидается `calculatorapp.exe`, а не `applicationframehost.exe`.
3. Активен сам REBOOT: результат `null`.
4. Блокнот активен, `limitApp {appIdentifier: "notepad.exe"}`. Ожидается: окно Блокнота свёрнуто (на панели задач оно есть, процесс жив, текст не потерян). Окно REBOOT показано и, по возможности, на переднем плане. Ответ `{applied: true, message: "«Блокнот» свёрнуто."}`. Если REBOOT только мигает на панели задач, запишите.
5. Блокнот в фоне, активен Проводник, `limitApp {appIdentifier: "notepad.exe"}`. Ожидается: ничего не сворачивается, окно REBOOT не меняется, `applied=false`, сообщение «Приложение сейчас не на переднем плане…».
6. В Блокноте открыт диалог «Сохранить как», `limitApp {appIdentifier: "notepad.exe"}`. Ожидается: сворачивается главное окно Блокнота вместе с диалогом.
7. UWP: Калькулятор активен, `limitApp {appIdentifier: "calculatorapp.exe"}`. Ожидается: окно Калькулятора свёрнуто.
8. Приложение, запущенное от имени администратора (например, Диспетчер задач), активно, `limitApp {appIdentifier: "taskmgr.exe"}`. Ожидается `applied=false` с объяснением; REBOOT не падает и не зависает.
9. Ни в одном сценарии процессы не завершаются, а запуск приложений не блокируется.

## 4. Известные ограничения

- Сбор идёт только пока REBOOT запущен. Фоновой службы нет.
- Видео или чтение без ввода дольше 120 с считается бездействием.
- UWP-приложения определяются через дочернее окно `Windows.UI.Core.CoreWindow` внутри `ApplicationFrameHost`. Если окно не найдено (например, во время анимации), записывается `applicationframehost.exe`.
- Если процесс нельзя открыть с `PROCESS_QUERY_LIMITED_INFORMATION` (отдельные системные или защищённые процессы), время ему не засчитывается.
- При разных процессах одного exe приложение считается одним (по имени exe).
- Опрос активного окна идёт раз в секунду, опрос бездействия — раз в 5 с. Погрешность границ ≈1–5 с.
