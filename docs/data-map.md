# REBOOT Data Map — архитектура сбора статистики (macOS / Windows)

> **Статус:** рабочая карта данных на 5 ноября 2026, версия политики `2026-11-05.3`. Составлена по исходному коду, контракту коллектора, контракту оболочки приложения (`docs/app-shell-contract.md`, канал `reboot/app`) и описанию архитектуры, которая реализуется сейчас. Это не захват сетевого трафика, не аудит платформ и не юридическое заключение. Перед публикацией сверить с выпускаемой сборкой. Публичный текст: `docs/privacy-policy.md`; краткая версия в приложении: `lib/content/privacy_policy.dart`. Предыдущая редакция карты описывала демо-сборку без сбора; `docs/privacy-policy-draft.md` сохранён как история.

## 1. Current app data and flows

Сбор статистики идёт только в режиме REAL, только после явного согласия в приложении и только пока процесс REBOOT запущен — с окном или в фоновом режиме (Menu Bar на macOS, системный трей на Windows, значок виден всегда). Отдельной фоновой службы нет; после «Завершить REBOOT», при выключенном компьютере, во сне и при блокировке сбор не ведётся, и это время не считается экранным. В режиме DEMO показываются заранее подготовленные примеры и статистика не собирается. Фоновый режим, автозапуск, фокус-сессии, цели и мягкие ограничения приложений, отчёты и ИИ-помощник новых видов данных об использовании не собирают. Время в окнах самого REBOOT в статистику не записывается. Единственное сетевое соединение — loopback к локальной Ollama (`http://127.0.0.1:11434` или `http://[::1]:11434`) и только при включённом ИИ-помощнике.

**Не собирается:** заголовки окон, URL, имена и содержимое документов, переписка, нажатия клавиш и вводимый текст, пароли, скриншоты, местоположение, контакты, полные пути к программам, время использования самого REBOOT (окна REBOOT исключаются из истории).

**Расположение папки данных:**

- macOS: `~/Library/Containers/com.reboot.app.rebootApp/Data/Library/Application Support/` (`usage-history/*.json` по месяцам, `consent.json`, `streak.json`, `feedback.json`, `focus.json`, `app_goals.json`); UserDefaults — `~/Library/Containers/com.reboot.app.rebootApp/Data/Library/Preferences/`.
- macOS, старый путь: ранние сборки ошибочно писали во вложенную папку `…/Containers/com.reboot.app.rebootApp/Data/Library/Containers/com.reboot.app.rebootApp/Data/Library/Application Support/`. `PrivacyDataStore.migrateLegacyData()` переносит файлы автоматически (best effort, без перезаписи: если файл уже есть в новой папке, старая копия остаётся). Обе папки внутри контейнера и удаляются вместе с ним.
- Windows: `%LOCALAPPDATA%\REBOOT\` — те же файлы плюс `settings.json`. Автозапуск — `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, значение `REBOOT`.
- Удаление приложения может не удалить эти папки; ручное удаление описано в политике.

**Platform scope:** карта описывает macOS и Windows. Нативные обработчики настроек для iOS/Android остаются в репозитории, но эта архитектура и политика их не покрывают.

## 2. Network, integrations, and recipients

- Проверка `grep` по `lib/` (`http`, `socket`, `analytics`, `telemetry`, `WebSocket`, `Uri.parse` и др.) 5 ноября 2026: сетевого кода, аналитики и телеметрии нет. Совпадения только по названию экрана `AnalyticsScreen` (локальные графики). Редакция `2026-11-05.3` вводит ИИ-помощник с HTTP-клиентом к локальной Ollama; повторить проверку после его внедрения: единственный разрешённый адрес — `http://127.0.0.1:11434`.
- Зависимости в `pubspec.yaml`: Flutter SDK и `cupertino_icons`; dev — `flutter_test`, `flutter_lints`. Сетевых и аналитических SDK нет.
- Контракт коллектора явно запрещает сеть и сбор заголовков, URL, нажатий и содержимого.
- macOS `Release.entitlements`: на момент первой проверки — только `com.apple.security.app-sandbox`. Для ИИ-помощника нужен `com.apple.security.network.client` (разрешает любые исходящие соединения; ограничение литеральным loopback `127.0.0.1` / `::1`, порт 11434, — в коде приложения). `DebugProfile.entitlements` содержит `com.apple.security.network.server` (стандартно для отладки Flutter); в release его нет.
- Получателей данных у оператора нет: нет сервера, учётных записей, синхронизации, облачных ИИ-сервисов, отчётов о сбоях.
- **Ollama (стороннее ПО пользователя):** получает сводку статистики по loopback, только при включённом ИИ-помощнике. Установлена и управляется пользователем; обработка запросов внутри Ollama (журналы, история, сеть, модели) вне контроля REBOOT. Локальный сервер Ollama доступен и другим программам на компьютере.
- Кроме сводки для локальной Ollama, данные покидают папку приложения только через файл экспорта (действие пользователя) или средства резервного копирования ОС (Time Machine, OneDrive для «Документов» и т. п.), которыми REBOOT не управляет.

**Инструмент разработки `tools/orchestrator.py` (не часть приложения):** Python-скрипт для разработчиков, координирует ИИ-модели при работе над кодом. Не входит в сборку, не читает папку данных пользователя. Сеть: по умолчанию локальная Ollama (`OLLAMA_HOST`, по умолчанию `http://127.0.0.1:11434`); с флагом `--cloud` и ручным вводом `CLOUD` отправляет в OpenAI API (`OPENAI_BASE_URL`, по умолчанию `https://api.openai.com/v1`) текст задачи, до 8000 символов файлов репозитория (`.dart`, `.py`, `.md`, `.yaml`, `.json`, `.swift`, `.kt`, `.xml`, кроме `.git`, `build`, `logs`, `tasks` и др.), `git status`/`git diff` и вывод `flutter analyze`/`flutter test`. Это поток данных разработки, а не пользовательских данных.

**Распространение:** приложение распространяется как готовая сборка; код сборки может быть обфусцирован. Обфускация не меняет состав, хранение и обработку данных и не является мерой защиты данных.
